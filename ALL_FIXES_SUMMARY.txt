## Fix #1: Streaming Punctuation Detection (CRITICAL)

**Issue**: Questions and exclamations didn't trigger sentence sending during streaming
**Impact**: Unnatural delays, bundled sentences instead of individual delivery

### Root Cause
`findDotPosition()` function only checked for periods (`.`), ignoring:
- Question marks: `?`
- Exclamation marks: `!`
- Japanese punctuation: `。` `？` `！`

### Files Modified
- `lib/chat_helper_functions.php` (lines 119-152)

### What Was Changed
Rewrote function to check ALL sentence-ending punctuation:
```php
// OLD: Only periods
$dotPosition = strrpos($s_string, ".");

// NEW: All punctuation
$eosPunc = getEndOfSentencePunctuation(); // .?!。？！
foreach ($punctChars as $punct) {
    $pos = mb_strrpos($s_string, $punct);
    // Find latest position, skip ellipsis
}
```

### Results
- ✅ Questions sent immediately when complete (75+ chars)
- ✅ Exclamations sent immediately when complete
- ✅ No more unnatural pauses
- ✅ Proper sentence-by-sentence streaming
- ✅ Ellipsis detection preserved
- ✅ Unicode support with mb_strrpos()

### Example Before/After
**Before**:
```
Stream: "Are you ready?" (ignored, waits for period)
Later: "Are you ready? Let's go." (both sent together)
```

**After**:
```
Stream: "Are you ready?" → SENT IMMEDIATELY
Stream: " Let's go." → SENT IMMEDIATELY
```

## Fix #2: Buffer Accumulation Error (MEDIUM)

**Issue**: totalBuffer accumulated entire buffer each iteration, causing exponential duplication
**Impact**: Memory waste, corrupted debug logs (if enabled)

### Root Cause
```php
$buffer .= $tmpData;        // ✓ Correct
$totalBuffer .= $buffer;    // ✗ Added entire buffer (duplicate everything)
```

### Files Modified
- `lib/data_functions.php` (line 2969)

### What Was Changed
```php
// OLD:
$totalBuffer .= $buffer;

// NEW:
$totalBuffer .= $tmpData;  // Only add new chunk
```

### Results
- ✅ No more exponential duplication
- ✅ Memory usage reduced
- ✅ Debug logs accurate (if enabled)
- ✅ No functional impact on game (totalBuffer only used for logging)

### Example Before/After
**Before**:
```
Iteration 1: totalBuffer = "Hello"
Iteration 2: totalBuffer = "HelloHello world"
Iteration 3: totalBuffer = "HelloHello worldHello world."
```

**After**:
```
Iteration 1: totalBuffer = "Hello"
Iteration 2: totalBuffer = "Hello world"
Iteration 3: totalBuffer = "Hello world."
```

## Fix #3: Cache Writing Failure (CRITICAL)

**Issue**: v1.0.3 reportedly not writing cache to disk
**Impact**: No cache efficiency gains, full context sent every request

### Root Cause
Invalid top-level `cache_control` parameter in API payload:
```php
$data = array(
    'model' => $this->_model,
    'messages' => $finalMessagesToSend,
    // ...
    "cache_control" => [      // ← DOESN'T EXIST IN ANTHROPIC API!
        "enabled" => true,
        "ttl" => "1h"
    ]
);
```

### Why This Was Wrong
- Anthropic API does NOT have a top-level `cache_control` parameter
- Cache control belongs on individual message content blocks (which was correct)
- This invalid parameter was likely rejected by API or caused confusion
- Prevented cache from being created

### Files Modified
- `connector/openrouterjsoncached.php` (removed lines 589-592)
- `connector/openrouterjsoncached_verbose.php` (removed lines 923-926)

### What Was Changed
Removed invalid top-level cache_control parameter entirely.

**Correct cache_control blocks remain at content level**:
- Line 403: System message content blocks
- Line 505: User message content (Gemini)
- Line 512: User message content (standard)

These are the CORRECT locations per Anthropic API documentation.

### Results
- ✅ Cache should now be created properly
- ✅ Cache efficiency should reach 80-90%
- ✅ Reduced token usage and costs
- ✅ Faster response times

### Testing Recommendations
1. Clear all cache temp files in `/tmp/` or connector directory
2. Make first request → Check log for `Create:XXXX` > 0
3. Make second request → Check log for `Read:XXXX` > 0
4. Verify efficiency: 80-90% is expected

**Log file**: `connector/_cached_perf.log`

## Fix #4: Cache Writing Failure #2 (CRITICAL)

**Issue**: Second cache bug - invalid "ttl" field in cache_control blocks
**Impact**: API might reject cache_control blocks with invalid field

### Root Cause
The cache_control block definition included an invalid "ttl" field:
```php
$cacheControlType = ["type" => "ephemeral", "ttl" => "1h"];  // ✗ Invalid!
```

### Why This Was Wrong
- Anthropic API does NOT accept a "ttl" field in cache_control blocks
- Cache control blocks should ONLY contain: `{"type": "ephemeral"}`
- TTL is controlled by the `anthropic-beta` header, NOT by cache_control content
- This header is set at line 671: `anthropic-beta: extended-cache-ttl-2025-04-11`

### Files Modified
- `connector/openrouterjsoncached.php` (line 311)
- `connector/openrouterjsoncached_verbose.php` (lines 364, 370)

### What Was Changed
```php
// OLD:
$cacheControlType = ["type" => "ephemeral", "ttl" => "1h"];

// NEW:
$cacheControlType = ["type" => "ephemeral"];  // TTL controlled by header
```

Also updated verbose logging:
```php
// OLD:
logMessage("[CACHE-VERBOSE] Cache control type: ephemeral, TTL: 1h");

// NEW:
logMessage("[CACHE-VERBOSE] Cache control type: ephemeral (TTL controlled by anthropic-beta header)");
```

### Results
- ✅ Cache control blocks now match API specification exactly
- ✅ Combined with Fix #3, caching should now work correctly
- ✅ Extended TTL (~1 hour) still active via anthropic-beta header

### Temp Directory Verification
User correctly identified that cache files are stored in `/temp/` not `/tmp/`:
- Location: `__DIR__ . "/../temp/"`
- Files: `system_cache_json_{NPC_NAME}.tmp`, `combined_dialogue_cache_json_{NPC_NAME}.tmp`
