## Investigation Status: CRITICAL BUG FOUND

## Issue #1: Invalid Top-Level cache_control Parameter

**File**: connector/openrouterjsoncached.php
**Lines**: 589-592

### The Bug

The connector adds an invalid top-level `cache_control` parameter to the API payload:

```php
$data = array(
    'model' => $this->_model,
    'messages' => $finalMessagesToSend,
    'stream' => true,
    // ... other params ...
    "cache_control" => [          // ← INVALID!
        "enabled" => true,
        "ttl" => "1h"
    ]
);
```

### Why This Is Wrong

**Anthropic API**: Does NOT have a top-level `cache_control` parameter. Cache control
is specified at the individual message content block level:

```json
{
  "model": "claude-3-5-sonnet-20240620",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "...",
          "cache_control": {"type": "ephemeral"}  ← At content level
        }
      ]
    }
  ]
}
```

**OpenRouter API**: Also does NOT have a top-level `cache_control` parameter with
"enabled" and "ttl" fields. OpenRouter uses Anthropic's caching format when
routing to Anthropic models.

### Impact

**Most Likely**: The API ignores this invalid parameter and accepts the request.
Cache control blocks at the content level (lines 403, 505, 512) would still work.

**Possible**: Some API implementations might reject the request entirely due to
unexpected parameters, causing cache writing to fail completely.

### Where Cache Control IS Correctly Applied

The connector DOES add cache_control correctly to message content blocks:

**System Messages** (line 403):
```php
$content = ['type' => 'text', 'text' => $finalSend];
if ($this->_provider_caching !== "OpenAI") {
    $content['cache_control'] = $cacheControlType;  // ← CORRECT
}
```

**User Messages - Gemini** (line 505):
```php
if (isset($completeEventList[$indexToCache]) && $this->_provider_caching != "OpenAI") {
    $completeEventList[$indexToCache]["cache_control"] = $cacheControlType;  // ← CORRECT
}
```

**User Messages - Standard** (line 512):
```php
if (isset($completeEventList[$lastIndex]) && $this->_provider_caching != "OpenAI") {
    $completeEventList[$lastIndex]["cache_control"] = $cacheControlType;  // ← CORRECT
}
```

These are the correct locations for cache_control blocks.

## Issue #3: Provider Caching Configuration

**File**: connector/openrouterjsoncached.php
**Line**: 259

```php
$this->_provider_caching = isset($GLOBALS["CONNECTOR"][$this->name]["provider_caching"])
    ? $GLOBALS["CONNECTOR"][$this->name]["provider_caching"]
    : "Anthropic";
```

### Possible Misconfiguration

If user has `provider_caching` set to something OTHER than "Anthropic", cache_control
blocks won't be added:

**Line 402-404**:
```php
if ($this->_provider_caching !== "OpenAI") {
    $content['cache_control'] = $cacheControlType;
}
```

This condition means:
- ✅ Adds cache_control if `_provider_caching` = "Anthropic"
- ✅ Adds cache_control if `_provider_caching` = "Gemini"
- ✅ Adds cache_control if `_provider_caching` = anything except "OpenAI"
- ❌ Skips cache_control if `_provider_caching` = "OpenAI"

**Check**: What if user didn't configure this and it's not defaulting properly?

**Default**: Line 98 and 259 both default to "Anthropic", so this should work.

## Diagnostic Steps to Identify the Issue

### Step 1: Check API Response Headers

Look for cache-related headers in the response:
- `x-cache-creation-input-tokens`
- `x-cache-read-input-tokens`
- Presence of these headers indicates cache is working

### Step 2: Check Payload Structure

Log the full `$data` payload (line 638):
```php
$this->_dataSent = json_encode($data, JSON_PRETTY_PRINT);
```

Check if:
1. Top-level `cache_control` parameter is being sent (should be removed)
2. Message content blocks have `cache_control` properly attached
3. Format matches Anthropic's expectations

### Step 3: Check Log Files

**File**: connector/_cached_perf.log (created at line 803)
```php
@file_put_contents(__DIR__ . DIRECTORY_SEPARATOR . "_cached_perf.log", $logPerfEntry, FILE_APPEND);
```

Check for entries like:
```
[2025-01-06] CACHE_PERF Lydia: Read:0 Create:0 New:2450 Total:2450 Efficiency:0.0%
```

If `Create:0` and `Efficiency:0.0%` every time, cache is NOT being created.

### Step 4: Check Temp Files

**Files**:
- `system_cache_json_{NPC_NAME}.tmp` (line 309)
- `combined_dialogue_cache_json_{NPC_NAME}.tmp` (line 310)

**Location**: Likely in `/tmp/` or connector directory

**Check**:
- Do these files exist?
- Are they being written?
- Do they contain serialized data?
