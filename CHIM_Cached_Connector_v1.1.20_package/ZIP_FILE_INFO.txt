CRITICAL FIX IN v1.1.20
=======================

**THINKING TOGGLE AND SETTINGS NOW SAVE CORRECTLY**

The thinking toggle, thinking tokens, and effort level settings were not saving
when you clicked the Save button in the LLM Connectors UI. They would reset to
OFF/empty after page reload.

Root Cause:
- Form fields were missing name attributes entirely
- HTML forms do not submit fields without name attributes
- This is basic HTML behavior that was overlooked

The Fix:
- Added name="metadata[toggle_thinking]" to checkbox
- Added name="metadata[thinking_tokens]" to number input
- Added name="metadata[effort_level]" to select dropdown
- Same pattern as all working metadata fields (provider_caching, etc.)
- PHP automatically collects metadata[key] into $_POST['metadata'] array
- LLMConnector class JSON-encodes and stores in database

Impact:
✅ Toggle Thinking checkbox now saves
✅ Thinking Tokens value now saves
✅ Effort Level selection now saves
✅ Works with o1, o3, o4, DeepSeek-R1, and other reasoning models

Location: ui/core/llm_connectors.php:375-376, 381, 384, 1459-1460, 1465, 1468

TROUBLESHOOTING
===============

Thinking toggle still not saving?
- Clear browser cache (Ctrl+Shift+Delete)
- Hard refresh page (Ctrl+F5)
- Verify file updated:
  grep 'name="metadata\[toggle_thinking\]"' ui/core/llm_connectors.php
- Check PHP error logs for permission issues
- Restart PHP-FPM or web server

Colons still being stripped?
- v1.1.18-1.1.20 fixed connector-side colon stripping
- If colons still stripped, issue is in post-processing pipeline
- Check returnLines(), unmoodSentence() functions
- This is a separate issue requiring investigation

minimize_quality_prompt not working?
- Check log/lastlog.log for diagnostic messages
- Verify setting in UI matches connector config
- Ensure DMgetCurrentModel() returns correct model name

Streaming issues?
- Check log/cache.log for buffer processing messages
- Verify finish_reason triggers flush
- Look for "Flush:" messages in logs
