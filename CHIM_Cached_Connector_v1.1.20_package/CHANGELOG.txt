v1.1.18 (2025/11/14)
--------------------
CRITICAL BUG FIX:
- Removed ALL colon stripping logic entirely
  * v1.1.16-17 attempts to be "smart" about when to strip colons
  * Problem: Talk is the most common action - colons should NEVER be stripped
  * Root cause: Misunderstanding of simple format specification
  * Format: (mood)(listener)(action)(target): message
  * The leading ':' is ALWAYS part of the format, regardless of action

THE FIX:
- Completely removed conditional colon stripping logic
- Colons are now preserved in ALL cases
- Lines 581-584 in openrouterjsoncached_helpers.php now just preserve colons
- Simple, correct behavior: never touch the leading ':'

IMPACT:
- Action descriptions always display correctly with leading ':'
- Talk actions display correctly with leading ':'
- No more edge cases or conditional logic
- Simpler, more maintainable code
- Fixes issue where v1.1.17 still stripped colons in some cases

Location: connector/openrouterjsoncached_helpers.php:581-584

v1.1.16 (2025/11/13)

- Fixed leading colon being stripped from action descriptions

THE FIX:
- Parse action field FIRST before deciding whether to strip colon
- ONLY strip colon for Talk actions: (mood)(listener)(Talk)(target) dialogue text

- Uses strcasecmp for case-insensitive comparison

IMPACT:
- Action descriptions now correctly display with leading ':'
- Fixes issue where "leans closer" appeared instead of ": leans closer"

v1.1.8 (2025/11/13)
-------------------
CRITICAL BUG FIXES:
- Fixed "Halfan" bug - Word concatenation from offset desync
  * Old: "Half an hour" → "Halfan hour"
  * New: Impossible due to index-based tracking

- Fixed message duplication - Length tracking errors
  * Old: Complex offset math caused re-sending
  * New: Simple sentence counter prevents duplicates

- Fixed lost sentences - Position calculation failures
  * Old: Sentences could be skipped
  * New: Index iteration ensures all sentences sent

- Fixed data loss at stream end - Trailing partials
  * Old: Incomplete text lost when max_tokens reached
  * New: Flush mechanism returns all content + adds period

- Fixed reasoning token interference
  * Old: <think> tags broke format detection
  * New: Preprocessing strips tags before parsing

NEW FEATURES:
- Reasoning token preprocessing
  * Handles <think>, <thinking>, <answer> tags
  * State machine for reliable stripping
  * Supports prefill cases (orphaned closing tags)

- Timeout fallback
  * Triggers at 100 characters without format
  * Graceful degradation to sentence splitting
  * Prevents complete failure when LLM ignores format

- Trailing partial flush
  * Returns unsent complete sentences first
  * Finds trailing text after last punctuation
  * Adds period if needed
  * Incremental return across multiple process() calls

ARCHITECTURE IMPROVEMENTS:
- Ultra-simple parser design
  * Single buffer (no separate sentence buffer)
  * Wait when ambiguous (only process when certain)
  * No offset math (index-based sentence tracking)
  * Combined metadata+sentence detection

- State variables
  * _reasoningState: 'NORMAL' | 'WAITING_FOR_REASONING_CLOSE'
  * _metadataEnd: Position where message starts (-1 = not found)
  * _sentencesSent: Count of sentences returned (simple counter)
  * _flushedPartial: Track if trailing partial was flushed
