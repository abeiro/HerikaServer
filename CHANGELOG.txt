Version 1.0.21 (2025-11-11)
---------------------------

Critical Bug Fixes:
-------------------
✓ **BUG #7 (CRITICAL): Fixed simple format with prefill showing only first word**
  - Problem: Only first word appeared in-game (e.g., only "lovely" instead of full message)
  - Root Cause: Missing critical code from v1.0.18 branch due to incomplete branch merge
    * 6 separate issues caused by branch divergence between development branches
  - Impact: Simple format completely broken with prefill - dialogue truncated to single word
  - Fixes Applied:
    1. _simpleFormatMessageStart initialization: Changed from 0 to -1
       * Allows proper detection of uninitialized state
    2. Added prefill position adjustment logic when calculating message start
       * Searches in bufferToParse (includes prefill) instead of raw buffer
       * Subtracts prefill length from message position to get correct offset
       * Prevents off-by-one errors that caused truncation
    3. Added fallback handling when message position not found
       * Logs warning and uses position 0 as safe fallback
       * Prevents silent failures
    4. Fixed streaming check: Changed from > 0 to >= 0
       * Position 0 is valid when message starts at buffer beginning
       * Previous check excluded valid position 0
    5. Fixed prefix construction to use trim(implode()) method
       * Properly combines prefix, speech reinforcement, and custom instructions
       * Removes extra whitespace that could break format parsing
    6. Added FUNCTIONS_ARE_ENABLED check for includeActions
       * Respects global function toggle setting
       * Matches behavior of v1.0.18
  - Modified: connector/openrouterjsoncached.php (6 separate fixes throughout file)
  - Modified: connector/openrouterjsoncached_verbose.php (same 6 fixes applied)
  - Result: Simple format with prefill now works correctly, full messages appear in-game

Technical Details:
------------------
The issue occurred because two parallel development branches diverged:
- Branch A (claude/aiagent-update-2.0.3-011CUs6A7NhcfwcMQJyoQ32j): Had v1.0.17/18 fixes
- Branch B (claude/fix-cache-connectors-011CV2UAD8LHFom1mofFyHt2): Had Bug #4/5 fixes

When continuing work on Branch B, the critical v1.0.17/18 fixes were not present,
causing simple format to break. This version restores all missing functionality

Version 1.0.20 (2025-11-11)
---------------------------

Critical Bug Fixes:
-------------------
✓ **BUG #6 (CRITICAL): Fixed simple format messages not appearing in-game**
  - Problem: Simple format responses were not appearing in CHIM event log or in-game
  - Root Cause #1: Regex pattern didn't handle LLMs outputting "(mood):" with colon
    * Pattern only matched "(mood) " without colon
    * When LLM used colon, parsing failed silently
  - Root Cause #2: No fallback handling when format parsing failed
    * When extractSimpleFormatFromBuffer() returned ['found'=>false], code fell through
    * Returned empty string on line 1020/1034, causing complete message loss
  - Impact: Messages completely lost when LLM didn't follow exact format
  - Fix #1: Updated regex to allow optional colons after format markers
    * OLD: `/^\s*\(([^)]+)\)\s*(.*)$/s`
    * NEW: `/^\s*\(([^)]+)\)\s*:?\s*(.*)$/s`
    * The `:?` makes the colon optional
  - Fix #2: Added comprehensive fallback error handling
    * Logs ERROR when simple format parsing fails
    * Logs first 200 chars of buffer for debugging
    * Returns entire raw buffer as dialogue instead of empty string
    * Marks format as "parsed" to prevent infinite re-parsing
    * Verbose connector includes complete buffer dump
  - Modified: connector/openrouterjsoncached_helpers.php (line 541 - regex pattern)
  - Modified: connector/openrouterjsoncached.php (lines 1004-1016 - fallback handling)
  - Modified: connector/openrouterjsoncached_verbose.php (lines 1667-1686 - fallback with verbose logging)
  - Result: Messages ALWAYS appear, even if LLM doesn't follow format correctly

Files Modified:
---------------
• connector/openrouterjsoncached_helpers.php - Updated regex to accept optional colon
• connector/openrouterjsoncached.php - Added fallback handling for parsing failures
• connector/openrouterjsoncached_verbose.php - Added fallback with verbose logging

Benefits:

Critical Bug Fixes:
-------------------
✓ **BUG #4 (CRITICAL): Fixed space removal in simple format streaming**
  - Problem: stripReasoningTokens() was being called on incremental streaming chunks
  - Root Cause: The function uses trim() which removes leading/trailing spaces from each chunk
  - Impact: Spaces between words were removed, concatenating words together
    Example: " sets down the leather" + " satchel" → "setsdowntheleathersatchel"
  - Fix: Only call stripReasoningTokens() once on the initial parsed message
  - Reasoning tokens are stripped from the complete first message, not from streaming chunks
  - Modified: connector/openrouterjsoncached.php (lines 1011-1014)
  - Modified: connector/openrouterjsoncached_verbose.php (lines 1630-1635, 1673-1682)
  - Result: Spaces are now preserved correctly during streaming

  - Modified: ui/core/llm_connectors.php (lines 487-494, 1499-1506)
  - Result: Users can now enter 4 decimal places as in v1.0.17
