CHIM Cached Connector v1.3.3 - Release Notes
============================================
Release Date: 2025-11-16
Compatible with: CHIM 2.0.3

OVERVIEW
--------
v1.3.3 removes the MINIMUM_SENTENCE_SIZE bottleneck for simple format,
enabling true sentence-by-sentence streaming. Previously, sentences were
buffered until reaching 75 characters before being sent to CHIM.

CRITICAL PERFORMANCE IMPROVEMENT
---------------------------------
This release significantly improves response time and perceived responsiveness
for simple format by sending each sentence immediately as it's generated,
rather than batching multiple sentences together.

CHANGES FROM v1.3.2
-------------------

1. REMOVED 75-CHARACTER BUFFERING BOTTLENECK FOR SIMPLE FORMAT

   **Problem:**
   Despite the connector properly splitting sentences and returning them one
   at a time, the main processing loop was buffering them until the total
   accumulated text reached 75 characters.

   **Example of the problem:**
   - Connector returns: "Hello there." (13 chars) → BLOCKED (< 75)
   - Connector returns: "How are you?" (12 chars) → BLOCKED (< 75)
   - Connector returns: "I'm doing well." (15 chars) → BLOCKED (< 75)
   - Connector returns: "What brings you here?" (21 chars) → BLOCKED (< 75)
   - Connector returns: "I need your help." (17 chars) → All 5 sent together (78 chars)

   **Solution:**
   Added conditional logic to bypass the 75-character minimum for simple format
   while preserving it for JSON format (which needs fragment accumulation).

2. NEW CONNECTOR METHOD: handlesSentenceSplitting()

   The connector now exposes a public method that indicates whether it handles
   sentence splitting internally:

   ```php
   public function handlesSentenceSplitting() {
       return ($this->_responseFormat === 'simple');
   }
   ```

   This allows the processing loop to apply appropriate logic based on format.

3. CONDITIONAL PROCESSING IN MAIN LOOP

   The main processing loop (lib/data_functions.php) now checks if the
   connector handles sentence splitting:

   - If YES (simple format): Bypass 75-character minimum, send immediately
   - If NO (JSON format): Apply original logic (accumulate fragments)

   **Before (v1.3.2):**
   - Simple format: Sentences buffered until ≥75 chars, sent in batch
   - JSON format: Same buffering behavior (correct for JSON)

   **After (v1.3.3):**
   - Simple format: Each sentence sent IMMEDIATELY as returned by connector
   - JSON format: UNCHANGED - still uses 75-char minimum (correct for JSON)

SAFETY GUARANTEES
-----------------

✓ JSON format completely unchanged
  - All original 75-character checks still apply
  - Fragment accumulation logic preserved
  - No risk of sending incomplete sentences

✓ Backward compatible
  - Uses method_exists() check before calling handlesSentenceSplitting()
  - Won't break other connectors that don't have this method
  - Safe fallback to original behavior

✓ Simple format only
  - Bypass only applies when _responseFormat === 'simple'
  - Connector's sentence splitting verified to work correctly
  - Returns complete sentences only, never fragments

✓ No data loss
  - All sentences still processed
  - Just sent faster, no batching delay
  - Translation checks still apply

✓ Edge cases handled
  - Missing method: falls back to original logic
  - Incomplete sentences: remain in buffer until complete
  - Translation enabled: processing deferred as before
  - Position check: must still find sentence ending
