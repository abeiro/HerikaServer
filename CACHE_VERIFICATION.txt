### 2. Cache Control Format ⚠️ POTENTIAL ISSUE

**Current implementation** (line 311):
```php
$cacheControlType = ["type" => "ephemeral", "ttl" => "1h"];
```

**Applied to content blocks** (line 403):
```php
$content['cache_control'] = $cacheControlType;
// Results in: {"type": "ephemeral", "ttl": "1h"}
```

### Anthropic API Specification

According to Anthropic's prompt caching documentation:

**Correct format**:
```json
{
  "type": "text",
  "text": "...",
  "cache_control": {"type": "ephemeral"}
}
```

**The "ttl" field does NOT belong in cache_control block!**

TTL is controlled by:
1. **Standard caching**: ~5 minute TTL (automatic)
2. **Extended caching**: ~1 hour TTL (enabled via `anthropic-beta: extended-cache-ttl-...` header)

The API does NOT accept a `"ttl"` field inside the `cache_control` object.

## How Caching Works (Summary)

### System Prompt Caching
1. Build system messages with format instructions, bio, etc.
2. Add cache_control to last system message content block (line 403)
3. Serialize and save to temp file (line 409)
4. On subsequent requests, load from file if less than 1 hour old

### Dialogue History Caching
1. Collect all user/assistant messages
2. Calculate cache control index (line 476)
3. Add cache_control to specific message in history (lines 505 or 512)
4. Save dialogue to temp file via manageCharacterEventList (line 458)
5. On subsequent requests, load and merge with new messages

### Cache Control Placement
- **Last system message**: Always cached
- **Dialogue message**: Based on `dialogue_cache_uncached_count` setting
  - Default: Last N messages remain uncached (dynamic/fresh content)
  - Older messages are cached (stable context)
