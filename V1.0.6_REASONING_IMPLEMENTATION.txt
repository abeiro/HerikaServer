OVERVIEW
===============================================================================

Version 1.0.6 adds complete Chain-of-Thought (CoT) reasoning support to the
CHIM Cached Connector, including:

1. **Reasoning Toggle** - Enable/disable reasoning for supported models
2. **Always-Strip Guarantee** - Reasoning tokens removed from output regardless of toggle
3. **Model Auto-Detection** - Automatic handling of OpenAI reasoning models
4. **Streaming Safety** - Prevents reasoning from appearing mid-stream
5. **Three-Layer Filtering** - API, streaming, and output layer protection

## 1. Configuration Options (conf/conf_schema.json)

### toggle_thinking (boolean, default: false)
- Enables/disables reasoning for models that support it
- When ON: Models use reasoning before responding
- When OFF: Models respond directly without explicit reasoning
- NOTE: Some models (o1, o3, o4, gpt-5*, DeepSeek-R1) always reason

### reasoning_effort (select, default: "medium")
- Options: "minimal", "low", "medium", "high"
- OpenAI-specific parameter controlling reasoning depth
- Higher effort = more thorough reasoning, higher token cost
- "minimal" option added for GPT-5+ models

### reasoning_model (deprecated)
- Marked as "wip" (work in progress, hidden from UI)
- Replaced by automatic model detection
- Legacy option kept for backward compatibility

## 2. Model Detection

### OpenAI Reasoning Models (isOpenAIModel)
Automatically detects and handles:
- o1, o1-mini, o1-preview
- o3, o3-mini, o3-pro
- o4, o4-mini
- gpt-5, gpt-5-pro, gpt-5-codex, gpt-5-mini, gpt-5-nano
- openai/[model], azure-[model] prefixed versions
- EXCLUDES: gpt-5-chat (not a reasoning model)

Special handling for these models:
- Uses max_completion_tokens instead of max_tokens
- Strips ALL incompatible parameters when reasoning enabled:
  - Removed: temperature, top_p, frequency_penalty, presence_penalty, etc.
  - Kept: model, messages, stream, reasoning, max_completion_tokens
  - Also kept: provider, transforms (for routing)

### Always-Reasoning Models (isAlwaysReasoningModel)
Models where reasoning cannot be disabled:
- All OpenAI reasoning models (o1, o3, o4, gpt-5*)
- DeepSeek-R1 (older version)
- r1-1776

For these models:
- Reasoning automatically enabled regardless of toggle state
- API parameters adjusted appropriately
- Reasoning tokens still stripped from output

## 3. Reasoning Token Filtering

### Supported Reasoning Markers
The system detects and strips these markers:

**XML-style tags:**
- `<think>...</think>`
- `<thinking>...</thinking>`
- `<reasoning>...</reasoning>`
- `<thought>...</thought>`
- `<reflection>...</reflection>`
- `<cot>...</cot>` (chain of thought)
- `<scratchpad>...</scratchpad>`

**Bracket-style tags:**
- `[THINK]...[/THINK]`
- `[THINKING]...[/THINKING]`

All markers are case-insensitive (e.g., `<THINK>`, `<Think>`, `<think>` all work).

### Three-Layer Filtering System

**Layer 1: API Request (reasoning.exclude=true)**
- Added to API payload: `reasoning: {exclude: true, enabled: ...}`
- Tells API to exclude reasoning from normal output
- Most reliable method, but not all models support it

**Layer 2: Streaming Detection (extractReasoningFreeContent)**
- Monitors incoming stream for unclosed reasoning markers
- If `<think>` appears without `</think>`, waits for completion
- Extracts content BEFORE unclosed markers
- Prevents reasoning from being sent to game mid-stream
- Ensures first actual sentence still streams immediately

**Layer 3: Final Output Stripping (stripReasoningTokens)**
- Applied to all return paths in connector
- Removes any reasoning that escaped Layers 1 & 2
- Failsafe guarantee that reasoning never reaches game
- Works for both JSON and simple response formats

## 4. Streaming Behavior

### Normal Streaming (No Reasoning)
```
Stream chunk 1: "Hello there"
Stream chunk 2: ". How are"
Stream chunk 3: " you?"
→ Output: "Hello there. How are you?" (sent at '.')
```

### Streaming with Complete Reasoning Blocks
```
Stream chunk 1: "<think>Should greet</think>Hello there"
→ Reasoning stripped: "Hello there"
Stream chunk 2: ". How are you?"
→ Output: "Hello there. How are you?" (sent at '.')
```

### Streaming with Incomplete Reasoning (Bug #1 Fix)
```
Stream chunk 1: "Hello there.<think>Analyzing tone"
→ Extracts content BEFORE marker: "Hello there."
→ Output: "Hello there." (sent immediately)
→ Buffered: "<think>Analyzing tone"

Stream chunk 2: ", seems friendly</think> How"
→ Complete block stripped: " How"
→ Buffer continues accumulating

Stream chunk 3: " are you?"
→ Output: " How are you?" (sent at '?')
```

**Key improvement from Bug #1 fix:**
- OLD: Entire buffer blocked when unclosed marker detected
- NEW: Content before unclosed marker extracted and sent
- Result: First sentence streams immediately, reasoning buffered

## 5. Response Format Handling

### JSON Format
```json
{
    "player": "Herika",
    "message": "Hello traveler!",
    "mood": "(happy)",
    ...
}
```
- Reasoning stripped from parsed `message` field
- Applied before JSON encoding

### Simple Format
```
(happy)(Herika)(none)Hello traveler!
```
- Reasoning stripped from both initial and incremental output
- Applied to parsed message content
- Parenthetical metadata preserved

## Function: stripReasoningTokens($text)
**Location**: lib/chat_helper_functions.php (lines 154-195)
**Purpose**: Remove reasoning markers from text

**Algorithm**:
1. Apply regex patterns for each marker type (case-insensitive, non-greedy)
2. Remove matched content including markers
3. Collapse ALL whitespace (including newlines) to single spaces
4. Trim result
5. Return cleaned text

**Whitespace handling**:
- `/\s+/` matches ALL whitespace (spaces, tabs, newlines)
- Replaced with single space
- Result: "Hello\n\nworld" → "Hello world"
- Rationale: Roleplay responses must be single line for game engine

## Function: hasUnclosedReasoningMarker($text)
**Location**: lib/chat_helper_functions.php (lines 199-227)
**Purpose**: Detect incomplete reasoning blocks during streaming

**Algorithm**:
1. For each marker type (think, thinking, reasoning, etc.)
2. Count opening tags (case-insensitive)
3. Count closing tags (case-insensitive)
4. If openCount > closeCount, return true
5. Return false if all markers balanced

**Use case**: Determines if streaming should wait for more data

## Function: extractReasoningFreeContent($text)
**Location**: lib/chat_helper_functions.php (lines 237-274)
**Purpose**: Extract reasoning-free content for safe streaming

**Algorithm**:
1. Strip all COMPLETE reasoning blocks first
2. Check if unclosed markers remain
3. If no unclosed markers, return cleaned text
4. If unclosed markers exist:
   a. Find position of first unclosed opening marker
   b. If marker at position 0, return false (wait for more data)
   c. If marker later in text, extract content BEFORE marker
   d. Return pre-marker content (trimmed)

**Critical behavior (Bug #1 fix)**:
- Input: "Hello there.<think>Partial"
- Cleaned: "Hello there.<think>Partial" (no complete blocks)
- First marker pos: 12 (position of `<think>`)
- Not at position 0, so extract: "Hello there."
- Return: "Hello there." (safe to send)

**OLD behavior (buggy)**:
- Input: "Hello there.<think>Partial"
- Detected unclosed marker → return false
- Result: "Hello there." not sent (blocked)

## Bug #1: Streaming Blocked by Unclosed Reasoning (CRITICAL - FIXED)

### Problem
When buffer contained a complete sentence followed by unclosed reasoning marker:
```
Buffer: "Hello there.<think>Partial reasoning"
```

**OLD behavior**:
- hasUnclosedReasoningMarker() returns true ✓
- extractReasoningFreeContent() returns false ✗
- Entire buffer processing skipped (continue)
- "Hello there." NOT sent to game ✗
- Waits for "</think>" before processing

**Impact**: Delayed streaming benefit, unnatural pauses

### Root Cause
extractReasoningFreeContent() was all-or-nothing:
- If ANY unclosed marker existed, returned false
- Did not attempt to extract pre-marker content
- Threw out valid sentences with the reasoning

### Solution
Modified extractReasoningFreeContent() to:
1. Strip complete reasoning blocks first
2. If unclosed markers remain, find position of first marker
3. If marker at position 0, return false (wait)
4. If marker at position >0, extract content BEFORE marker
5. Return pre-marker content if it exists

**NEW behavior**:
```
Buffer: "Hello there.<think>Partial reasoning"
→ No complete blocks to strip
→ Unclosed marker detected at position 12
→ Position > 0, extract: "Hello there."
→ Return: "Hello there." ✓
→ Buffered for next iteration: "<think>Partial reasoning"
```

### Code Changes
**File**: lib/chat_helper_functions.php (lines 237-274)

**Added logic**:
```php
// Find position of first unclosed opening marker
$markers = [
    '<think>', '<thinking>', '<reasoning>', '<thought>', '<reflection>',
    '<cot>', '<scratchpad>', '[THINK]', '[THINKING]'
];

$firstMarkerPos = false;
foreach ($markers as $marker) {
    $pos = stripos($cleaned, $marker);
    if ($pos !== false && ($firstMarkerPos === false || $pos < $firstMarkerPos)) {
        $firstMarkerPos = $pos;
    }
}

// If unclosed marker is at the start, wait for more data
if ($firstMarkerPos === 0) {
    return false;
}

// If unclosed marker is later in the text, return content before it
if ($firstMarkerPos !== false) {
    return trim(substr($cleaned, 0, $firstMarkerPos));
}
```

### Results
- ✅ First sentences stream immediately even when followed by reasoning
- ✅ No more unnatural delays
- ✅ Reasoning still properly buffered and stripped
- ✅ Maintains all safety guarantees

## 1. Nested Reasoning Tags (Low Priority)

### Issue
If LLM outputs nested markers of the same type:
```
<think>
  Outer reasoning
  <think>Inner reasoning</think>
  More outer reasoning
</think>
```

### Behavior
Regex `/<think>.*?<\/think>/is` matches from FIRST `<think>` to FIRST `</think>`:
- Removes: `<think>  Outer reasoning  <think>Inner reasoning</think>`
- Leaves: `  More outer reasoning\n</think>`
- Orphaned `</think>` remains in output

### Mitigation
- LLMs rarely output nested markers of same type
- If different types nested, works correctly:
  ```
  <think>Outer<reasoning>Inner</reasoning>More</think>
  ```
  Results in both stripped correctly

### Status
Documented as known limitation. Acceptable for v1.0.6.

### Potential Fix (Future)
- Implement proper parser with nesting depth tracking
- Or add cleanup pass for orphaned closing tags
- Or explicitly instruct models not to nest markers

## 2. Ellipsis-Only Sentences

### Behavior
```
Stream: "I was thinking..."
→ Last char is '.', marked as incomplete (might be ellipsis)
→ Waits for more content
```

Eventually:
```
Stream: "I was thinking... maybe we should go?"
→ Sent when '?' arrives
```

### Rationale
In streaming context, trailing "..." likely means more content coming.
Can't distinguish between ellipsis and sentence end mid-stream.

### Mitigation
End-of-stream handler catches any remaining buffer:
```php
if (trim($buffer)) {
    $buffer = stripReasoningTokens($buffer);
    Logger::info("REMAINING DATA <$buffer>");
    // Send remaining content even without final punctuation
}
```

## 3. Minimum Sentence Size (75 characters)

### Behavior
Sentences shorter than 75 characters not sent individually:
```
"Hi." → Too short, waits
"Hi. How are you?" → Sent together when 75+ chars reached
```

### Rationale
Intentional throttling to avoid sending tiny fragments.
Maintains smooth streaming without excessive micro-updates.

### Configuration
Defined by MINIMUM_SENTENCE_SIZE constant (currently 75).

## 4. GPT-5-chat Exclusion Pattern

### Issue
Code excludes models with "gpt-5-chat" substring:
```php
stripos($s_model, "gpt-5-chat") === false
```

This excludes:
- "gpt-5-chat" ✓ (intended)
- "gpt-5-chatbot" ✗ (might be too broad)
- "gpt-5-chat-pro" ✗ (might be too broad)

### Rationale
Conservative approach: Better to incorrectly exclude edge-case models
than incorrectly include gpt-5-chat as reasoning model.

### Status
Acceptable. These hypothetical models don't exist yet.

## 5. Reasoning Parameter Always Sent

### Behavior
Reasoning object sent even when enabled=false:
```php
$reasoning = [
    "exclude" => true,
    "enabled" => false,  // Even when false, object is sent
];
$data['reasoning'] = $reasoning;
```

### Rationale
- exclude:true should always be set to catch stray reasoning tokens
- Some APIs might need this to properly filter output
- Empty/false object vs no object distinction unclear in API docs

### Status
Acceptable. No known negative impact. May actually be correct behavior.
