CHIM Cached Connector v1.1.19 - Installation Instructions
==========================================================

IMPORTANT: This version (v1.1.19) fixes a CRITICAL bug where the thinking
toggle and related settings were not saving. It also adds comprehensive
diagnostic logging to help debug colon stripping issues. Upgrading is
highly recommended if you use thinking/reasoning models.


QUICK INSTALL (Recommended)
============================

1. BACKUP YOUR FILES
   -----------------
   Before installing, backup these files in case you need to revert:
   - connector/openrouterjsoncached.php
   - connector/openrouterjsoncached_verbose.php
   - connector/openrouterjsoncached_helpers.php
   - connector/__jpd.php
   - lib/tokenizer_helper_functions.php
   - lib/chat_helper_functions.php
   - lib/core/llm_connector.class.php
   - ui/core/llm_connectors.php
   - ui/core/core_profiles.php
   - conf/conf_schema.json

2. EXTRACT ZIP
   -----------
   Extract all files from CHIM_Cached_Connector_v1.1.19_package.zip

3. COPY FILES
   ----------
   Copy to your CHIM installation directory, preserving folder structure:

   connector/*     → [CHIM]/connector/
   lib/*           → [CHIM]/lib/
   functions/*     → [CHIM]/functions/
   conf/*          → [CHIM]/conf/
   ui/*            → [CHIM]/ui/
   prompts/*       → [CHIM]/prompts/

4. CLEAR CACHE (IMPORTANT!)
   -------------------------
   Delete these cache files:
   - [CHIM]/temp/system_cache_*.tmp
   - [CHIM]/temp/combined_dialogue_cache_*.tmp

5. RESTART CHIM
   ------------
   Restart your CHIM server/application
   If using PHP-FPM or opcache, restart PHP service

6. VERIFY INSTALLATION
   -------------------
   a) Check version:
      - log/cache.log should show "v1.1.19 initialized"

   b) Test thinking toggle:
      - Go to LLM Connectors UI
      - Enable "Toggle Thinking"
      - Set "Thinking Tokens" to 1000
      - Select "Effort Level"
      - Click Save
      - Reload page - settings should persist ✅

   c) Check diagnostic logging:
      - Enable simple format
      - Test with NPC dialogue
      - Check log/chim.log for [unmoodSentence] entries
      - Should see ⚠️ or ✅ markers

-----------------------------
1. Check version in logs:
   tail -f [CHIM]/log/cache.log | grep "initialized"
   Should show: "OpenRouter Cache Connector v1.1.19 initialized"

2. Test thinking toggle:
   - Open browser to LLM Connectors UI
   - Select a connector to edit
   - Find "Toggle Thinking" checkbox
   - Enable it
   - Set "Thinking Tokens" to 1000
   - Select "Effort Level" = "medium"
   - Click "Save" button
   - Wait for page to reload
   - Settings should still be there (not reset to OFF) ✅
   - Open browser dev console (F12)
   - Check for any JavaScript errors

3. Check form has metadata field:
   - Right-click page, select "View Page Source"
   - Search for: name="metadata"
   - Should find: <input type="hidden" name="metadata" value='...'>
   - If missing, ui/core/llm_connectors.php wasn't updated correctly

4. Test simple format with diagnostic logging:
   - Enable response_format = "simple" in configuration
   - Send test message to LLM
   - Check log/chim.log for [unmoodSentence] messages
   - Should see markers like ⚠️, ✅, or ❌

5. Verify colon preservation in connector:
   - grep -A 3 "Do NOT strip" [CHIM]/connector/openrouterjsoncached_helpers.php
   - Should show the colon preservation comment block

CONFIGURATION AFTER INSTALL
============================

1. RESPONSE FORMAT
   ---------------
   In your connector configuration, set:

   response_format = "simple"  // Recommended with v1.1.19

   Or:

   response_format = "json"  // Classic format

2. FIELD CONTROL
   -------------
   Enable/disable specific fields:

   include_mood_requirement = true
   include_listener_requirement = true
   include_actions_list = true
   include_target_requirement = true

3. CACHE SETTINGS
   --------------
   provider_caching = "Anthropic"  // or "OpenAI", "Gemini"
   max_dialogue_cache_context_size = 200
   dialogue_cache_uncached_count = 4

4. MINIMIZE QUALITY PROMPT
   -----------------------
   minimize_quality_prompt = true  // For Claude 3.5+, GPT-4+, Gemini 2.0+, etc.
   minimize_quality_prompt = false  // For older/smaller models

5. THINKING/REASONING SETTINGS
   ---------------------------
   In LLM Connectors UI:
   - Toggle Thinking: ON (for o1, DeepSeek-R1, etc.)
   - Thinking Tokens: 1000-4000 (Anthropic/Gemini only)
   - Effort Level: low/medium/high (OpenAI reasoning models only)


TROUBLESHOOTING
===============

PROBLEM: Thinking toggle still not saving
SOLUTION: - Clear browser cache (Ctrl+Shift+Delete)
          - Verify ui/core/llm_connectors.php was updated
          - Check browser console for JavaScript errors
          - View page source, search for name="metadata"
          - Should find <input type="hidden" name="metadata">
          - If missing, file didn't update correctly

PROBLEM: JavaScript error "form.metadata is undefined"
SOLUTION: - The hidden metadata field is missing
          - Re-copy ui/core/llm_connectors.php from package
          - Clear PHP opcache if enabled
          - Restart web server

PROBLEM: Settings save but disappear on page reload
SOLUTION: - Check database permissions
          - Look for SQL errors in error logs
          - Verify core_llm_connector table structure
          - Check metadata column can store JSON

PROBLEM: Version still shows v1.1.18 or earlier after upgrade
SOLUTION: - Clear PHP opcache if enabled
          - Restart web server
          - Check that files were actually copied (permissions issue?)
          - Verify file modification timestamps

PROBLEM: No diagnostic logging appearing in log/chim.log
SOLUTION: - Verify lib/chat_helper_functions.php was updated
          - Check that simple format is enabled
          - Look for [returnLines] or [unmoodSentence] in logs
          - Ensure log directory is writable

PROBLEM: Colons still being stripped
SOLUTION: - Check diagnostic logs in log/chim.log
          - Look for "❌ COLON WAS STRIPPED" markers
          - Identify which checkpoint shows the stripping
          - Report findings for proper fix

PROBLEM: Cache not working after upgrade
SOLUTION: - Verify you cleared cache files
          - Check provider_caching matches your API provider
          - Look for cache statistics in _cached_perf.log

PROBLEM: Simple format not working
SOLUTION: - Verify response_format = "simple" in configuration
          - Check log/cache.log for parser initialization
          - Look for timeout fallback messages (triggers at 100 chars)

PROBLEM: minimize_quality_prompt not working
SOLUTION: - Check log/lastlog.log for diagnostic messages
          - Verify setting is in correct configuration section
          - Check model name matches configuration key


ROLLBACK PROCEDURE
==================

If you need to revert to your previous version:

1. Stop CHIM

2. Restore from backup:
   cp ~/chim_backup_YYYYMMDD/* [CHIM]/connector/
   cp ~/chim_backup_YYYYMMDD/* [CHIM]/lib/
   cp ~/chim_backup_YYYYMMDD/* [CHIM]/ui/core/
   (restore other files as needed)

3. Clear cache:
   rm -f [CHIM]/temp/system_cache_*.tmp
   rm -f [CHIM]/temp/combined_dialogue_cache_*.tmp

4. Restart CHIM and web server
